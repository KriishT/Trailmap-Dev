# Scanner accuracy

Generated by `npm run eval` for scanner 0.2.0. Do not edit by hand.

Each fixture under `packages/scanner/fixtures/<name>/repo` has a hand-written `expected.json`. Precision is the share of reported items that are correct; recall is the share of real items that were found. CI fails if service to service or service to vendor precision drops below 90.0%, or recall below 80.0%, if any fixture's output is not byte-identical across runs, or if the trap repository or this repository produce a phantom connection.

## How to read these numbers

The fixtures were written together with the scanner, so they describe the situations it was built for. Perfect scores here show that those situations are handled and that nothing regressed; they are not an estimate of accuracy on an arbitrary codebase, which will be lower. Every fixture is a small, single-purpose repository; real repositories add dynamic URLs built at runtime, service discovery through a registry, infrastructure modules from other repositories and code generation, none of which static analysis can fully resolve. Treat `low` and `medium` confidence edges as prompts to review, and use the overrides in the product to confirm or hide them.
